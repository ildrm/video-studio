# Frontend architecture

Status: proposed • Owner: frontend architect • Dependencies: [schema](canonical-editor-state-and-schema.md), [preview](browser-preview-engine.md), [UX](../02-ux-ui/ux-strategy-and-information-architecture.md).

Recommend React and TypeScript with a Next.js application shell; version selection and browser support require phase-0 validation. Domain packages: project commands, timeline math, media client, preview compositor, UI components, API client, localization and accessibility. Server remains authority for permissions, revisions and render. Isolate rendering computation in workers when feasible; do not put secrets in client bundles. Components receive IDs, data, selection and callbacks, not mutable global objects. `MediaBrowser` and `UploadManager` own asset selection and resumable progress; `ProjectDashboard` lists scoped projects; `Timeline`, `TimelineTrack`, `TimelineClip`, `TimelinePlayhead`, `TimelineRuler` emit typed edit commands; `PreviewMonitor` and `TransformControls` emit positions; `PropertyInspector`, `CaptionEditor`, `TranscriptEditor`, `AudioMixer`, `ColorInspector`, `EffectsBrowser`, `GraphicsPanel`, `ThumbnailCanvas` emit typed property edits; `RenderDialog`, `ExportSettings`, `JobProgress`, `CollaborationPanel` use API state. They expose focus and error state, announce async updates, and never mutate persisted data directly. Test model independently from rendering; real browser tests cover keyboard and proxy fallback. No stack is implemented yet.
