# Browser preview engine

Status: proposed • Owner: browser media engineer • Depends on [schema](canonical-editor-state-and-schema.md) and [parity decision](../07-architecture/decisions/ADR-003-preview-render-parity.md).

Use authorized proxy URLs, browser media decoding, a canvas compositor and Web Audio clock; feature-detect WebCodecs and individual codec support, fall back to HTML media or server preview. Preview and final render interpret the same project revision. Classify each operation: timing-exact (validated cuts and placement within one output-frame tolerance; proxy pixels are not lossless), approximate (color, fonts and some effects), or server-rendered (unsupported compositing); display badges before export. Preload neighboring clips under a memory budget; seek using presentation timestamps and release decoded frames. Align video to audio master clock, report dropped frames; scrub may use reduced-resolution proxy, frame step resolves target output frame. Inaccessible assets or unsupported decoder offer regenerate proxy/server preview, never silently remove media. Browser platform support is measured during phase 0. Acceptance: test representative images, timing and audio against rendered fixtures with declared tolerances and user-visible approximation.
