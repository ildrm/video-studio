# Collaboration and sharing

Status: proposed; external review is phase 5 • Owner: collaboration lead • Related: COL-001/002, PRJ-002, SEC-001. Dependencies: [access rules](../01-product/user-roles-and-permissions.md), [API](openapi.yaml).

Phase 1 editing uses optimistic revision concurrency. Stale If-Match saves receive 412 with preserved local draft; real-time merging/CRDT is outside initial scope. Presence must never imply safe simultaneous editing. Later comments reference projectId, immutable revision, sequenceId and tick; edits on another revision leave comments visibly anchored to the original, with optional explicit reviewed reanchoring.

A share binds exactly one project revision and verified artifact from that revision. Expiry is mandatory; permission is view or comment, and export download is a separate allowDownload flag default false. A token cannot return editable project JSON, original media, workspace assets or membership data. Review playback uses a dedicated authorized derivative; allowDownload=false restricts download issuance but cannot prevent a viewer recording the screen. Store token hash only; show token once at creation, suppress referrers and cache/log exposure, and rotate by revoking then creating another share. Membership/editor role alone does not confer share.manage.

Revocation immediately rejects future API and gateway access and closes subscriptions. Direct signed object URLs already issued retain their documented TTL; use gateway-mediated review when immediate access revocation is required. Invitations require active actor authority at issue and acceptance, named scope/role, single-use token and expiry. Owner transfer requires current owner initiation and active recipient acceptance atomically, keeping at least one owner. Permission changes affect pending proposals and subsequent job/download authorization; artifact retention never grants access. Acceptance: expiry, foreign artifact, revision mismatch, download restriction, stale revision and revocation races. Public-review/comment APIs remain explicitly uncontracted until phase 5.
