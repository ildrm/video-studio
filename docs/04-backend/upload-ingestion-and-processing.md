# Upload, ingestion and processing

Status: proposed • Owner: media platform engineer • Related: MED-001/002, ADM-001. Dependencies: [storage](media-storage-and-lifecycle.md), [jobs](job-queues-workers-and-render-orchestration.md), [OpenAPI](openapi.yaml).

1. Authorize asset.upload and atomically reserve declared bytes. Create session with server-assigned key, size, full-file SHA-256, partSize, partCount and expiry. File count, byte, duration, pixel and stream ceilings are deployment policy; schema ceilings are not entitlement guarantees.
2. Issue a short-lived PUT grant for one validated part number and expected checksum. Enforce the server's size boundaries, checksum headers, exact object/upload ID and CORS origin. Client cannot choose bucket/key or multipart ID. Configure CORS to allow only required headers/methods and expose required ETag/checksum headers.
3. GET parts reconciles authoritative object-store part metadata; browser state alone is insufficient for resume. Part checksum and opaque ETag are distinct. Do not assume multipart ETag is a full-file content hash. Compute the original SHA-256 using an incrementally verified server/worker path when the storage provider cannot prove the chosen full-object checksum. See [object integrity documentation](https://docs.aws.amazon.com/AmazonS3/latest/userguide/checking-object-integrity-upload.html).
4. Complete idempotently: compare part count/order/size/checksum, move state to finalizing, finish object-store upload, enqueue one ingestion job via outbox. Reconcile a crash between object completion and DB commit; do not repeat billing or create duplicate asset versions. API returns 202 with Job. Session becomes completed when original bytes are verified and registered; asset may still be inspecting/processing.
5. Probe hostile bytes in sandbox; verify actual dimensions, duration, streams and configured bounds, then generate independent thumbnails, waveform and proxy. Asset states: quarantined → inspecting → processing → ready, with failed/deleted terminal handling. Ready requires mandatory derivatives for the intended workflow. Original bytes remain immutable.

Pause is local to client transfer, not a fabricated server session state. Session states are created, uploading, finalizing, completed, failed, expired, cancelled. Failed/expired sessions do not reuse an object key; start a fresh session after reconciliation. Cancel aborts multipart, denies new grants and schedules bounded cleanup. Already issued URLs can remain valid until expiry; incomplete/staged uploads cannot become registered assets after cancellation. Quota reservations release only after durable accounting identifies retained bytes. Reject encrypted/unsupported/malformed inputs with safe diagnostics, never user paths or probe logs. Image sequences use bounded explicit manifests, not filesystem globs. Acceptance: resume, checksum mismatch, duplicate complete, expiry, cancel race and crash after storage completion (AT-02, AT-22, AT-24).
