# API design and contracts

Status: proposed core contract • Owner: API architect • Related: PLT-001/002, PRJ-001/002, MED-001, CAP-001, AUD-003, EXP-001, SEC-001. Dependencies: [OpenAPI](openapi.yaml), [project schema](../03-frontend/schemas/project-v1.schema.json), [authorization](authentication-authorization-and-tenancy.md).

All API paths are under `/v1`; JSON uses camelCase, UUID resource IDs and UTC RFC 3339 timestamps. OpenAPI is JSON-formatted YAML and references the single project JSON Schema. The core slice covers session inspection/logout, workspaces/projects, revision reads/saves, multipart upload, asset metadata, presets, speech/render jobs, polling/SSE, exports, notifications and quotas. Sharing mutations are explicitly phase 5. Registration/password/MFA/verification screens are delegated to the selected OIDC provider; authorization redirects/callback and later membership, comment, billing and public-review APIs need separate contracts before those features ship. A listed phase is not implementation availability.

Project lifecycle extends the contract with `PATCH /workspaces/{workspaceId}/projects/{projectId}` for name/archive state and `POST .../{projectId}/duplicate` for a copy of the latest saved document. `project.admin` covers rename/archive/restore and is limited to owner/administrator roles in the intended role model; the development implementation currently permits owners only. Lists select active or archived projects and bind cursors to the literal name search. Archive preserves history and blocks editing/rendering until restoration. Draft validation checks canonical state and authorized references without saving or silently rebasing a stale revision.

Manual caption font installation uses `POST /workspaces/{workspaceId}/fonts` with the supported font ID. The server copies a trusted font and its exact license notices into an immutable workspace asset; missing font or notices fail explicitly. Font notices are available through the authenticated asset license endpoint. Arbitrary font upload and complete font licensing administration remain separate work.

## Authentication and authorization

Cookie name is `__Host-studio-session`, Secure, HttpOnly, Path=/, SameSite=Lax. GET /session returns a session-bound CSRF token; state-changing API requests require X-CSRF-Token plus an allowed Origin. OIDC callback validates state, nonce and PKCE independently. No cookie or token belongs in URLs/logs. Each operation declares x-permission and x-phase, enforced on the addressed workspace and every referenced asset/job/artifact. Return 404 for missing or inaccessible objects; use 403 only when the actor already has visibility but lacks the requested action. Replays recheck current authorization and expiry.

## Revision and idempotency

GET current revision returns ETag `"rev-7"` for document revision 7. PUT supplies If-Match `"rev-7"` and document.revision=7; a successful transaction persists and returns document revision 8 with ETag `"rev-8"`. A stale precondition returns 412 `REVISION_MISMATCH`; missing precondition returns 428; body/header disagreement returns 400. All validation and compare-and-swap occur in one transaction. RFC 9110 defines If-Match failure as 412; 409 is reserved for idempotency payload conflicts or invalid resource-state changes. See [HTTP semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1).

Creation, saves, job submission and upload completion require an idempotency key. Scope it to actor, workspace (where present), method and canonical path; compare canonical request body and precondition hash. Retain result for a proposed 24 hours. Identical replay returns original outcome without new side effects; changed payload/precondition returns 409 `IDEMPOTENCY_CONFLICT`. After expiry, query existing resource/job before creating another; API does not promise unbounded duplicate suppression. Persist outbox and result atomically. Issuing a short-lived URL is deliberately renewable and is not cached as a durable idempotent result.

## Responses and errors

Synchronous creation returns 201 + Location; async admission returns 202 + Location pointing to a Job. Deletes return 204 without content. Lists have typed items, opaque cursor, limit 1–100 and stable createdAt/id ordering; cursor is scope/filter-bound and must not grant access. Events order by sequence. Errors use `{error:{code,message,requestId,details?}}`: 400 validation, 401 session, 403 action/CSRF, 404 hidden or absent, 409 state/key conflict, 410 expired authorized history/artifact, 412 precondition, 413 configured size ceiling, 428 missing precondition, 429 quota/rate and 503 temporary outage. No stack, paths, provider secrets, foreign IDs or signed URLs in details. Retry-After is returned when known. Proposed limits are deployment policy, not invented service capacities.

Structured Job state and typed response models are in OpenAPI. Polling events and text/event-stream are distinct endpoints; SSE is advisory and can reconnect, while GET Job is authoritative. Speech jobs return reviewed artifacts and do not mutate the project. Apply reviewed results through a separate revision save. Complete per-feature APIs and provider consent/voice catalogs remain open release work. Acceptance: AT-22 covers request/response validation, CSRF, precondition, typed pagination and duplicate admission.
