# Authentication, authorization and tenancy

Status: proposed • Owner: security architect • Dependencies: [permission matrix](../01-product/user-roles-and-permissions.md).

Use an established identity provider via OIDC authorization-code flow with PKCE, state and nonce verification; server sessions in __Host-studio-session Secure, HttpOnly, SameSite=Lax cookies with Path=/ and no Domain, CSRF protection and rotation. Require verified identity for workspace/content mutations; logout and identity recovery remain available to the account under provider/session policy; MFA and password recovery depend on selected provider and policy. Server derives actor and workspace on every request; deny by default, validate project/resource scope and action with current membership. No client-provided role is trusted. Sharing uses random hashed tokens, minimal permission, expiration and revocation; membership changes invalidate future access and active sessions as policy permits. Signed URLs remain valid until expiry, so use short TTL and avoid claiming immediate revocation. Service identities have workload-scoped credentials and job-scoped object access. Support access is time-limited, authorized and auditable; platform administration does not imply access to content. Avoid ID enumeration, rate-limit auth and audit sensitive actions. Test actor × scope × action including revocation and cross-tenant requests.

Use CSP, output encoding and dependency review against script compromise; local browser storage is not a trusted secret store. Enforce 404 for inaccessible resource IDs and 403 for a visible scope lacking action permission. Rate limits and audit logs must not leak account existence. Session, CSRF, provider callback, service identity and review tokens are distinct credential types.
