# Transcription, diarization and transcript editing

Status: proposed design; not implemented or tested. Owner: AI engineering lead. Dependencies: [canonical model](../03-frontend/canonical-editor-state-and-schema.md), [feature catalog](../01-product/feature-catalog.md), [release gates](../09-delivery/phase-gates-and-definition-of-done.md).

Input is an authorized audio stream or derived bounded segment plus language hint and project/asset version. ASR adapter returns text segments, optional word timestamps, language and confidence with provenance; aligner and diarizer are independent optional capabilities. Timestamps use source time and map to 240,000 project ticks through the clip's trim/speed mapping. Preserve overlaps, uncertainty and speaker labels as provisional; never infer identity from speaker labels.

Users correct text, timings, names and speakers, split/merge cues and approve caption export. Transcript edits create a new revision; changing words alone does not delete source audio. A requested text-based cut generates a reversible operation plan from aligned words, including margins; require user review and flag uncertain timing. Stale transcript mappings are surfaced after source or timeline edits. Consent and provider retention must cover speech processing; record language/model/version, billed duration and deletion requests. Retry only transient failures and show unsupported language or missing alignment. Evaluate WER/CER by language and domain, diarization error where labeled data exists, timing error and user correction time across accents, noise and overlapping speakers; disclose benchmarks and sample limitations.
