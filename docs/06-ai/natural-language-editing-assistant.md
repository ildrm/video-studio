# Natural-language editing assistant

Status: proposed design; not implemented or tested. Owner: AI engineering lead. Dependencies: [canonical model](../03-frontend/canonical-editor-state-and-schema.md), [feature catalog](../01-product/feature-catalog.md), [release gates](../09-delivery/phase-gates-and-definition-of-done.md).

The assistant receives a user request and the minimum authorized project summary; transcript, filenames and media content are untrusted data, not instructions. It proposes a schema-validated list of allowlisted operations against a specific immutable revision. Each operation references existing tenant-scoped IDs, ranges in ticks, typed parameters, dependencies, expected effect, reversibility and estimated usage. The server independently validates authorization, ranges, capabilities and budget. Reject arbitrary commands, filter expressions, network destinations and unauthorized assets; a model never invokes worker or external APIs directly.

Flow: interpret → inspect revision → construct plan → validate assets/capabilities → estimate cost → display timeline diff and warnings → obtain approval for every proposed project mutation and for costly or external actions → apply non-destructive edits as one revision with optimistic concurrency → run explicitly authorized jobs → verify → present results and rollback. If the revision changed, replan or obtain approval on a new diff. Example: “remove long pauses, make 9:16, caption and duck music” yields candidate pause ranges, editable crop, generated caption job and explicit mixer settings; it cannot silently delete media or publish. Treat provider output as untrusted; show uncertainty and refuse unsupported requests. Test injection in captions and metadata, cross-tenant IDs, malformed schemas, stale revisions, cost escalation and cancellation.
