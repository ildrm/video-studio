# Canonical feature catalog

**Status:** Proposed scope, not implementation. **Owner:** Product lead. **Dependencies:** [functional requirements](functional-requirements.md), [permissions](user-roles-and-permissions.md), [roadmap](release-scopes-and-roadmap.md), [workflows](user-journeys-and-workflows.md). IDs identify feature families, not claims of existing capability. Classification follows the capability, not only the phase: core platform/editing is proposed core, later professional tooling proposed advanced, semantic AI experimental, and provider-backed speech/publishing external integration even when speech begins in phase 2. Phase 0 is investigation; phase 6 hardens all capabilities. Priorities follow phase ordering (1–2 P0/P1; 3–5 later). Roles: authorized creator/editor unless specified; administrative, service and viewer limits are in the permissions matrix.

Authenticated workspace features require a valid scoped session; account entry/recovery and explicitly authorized review links use their separate authentication paths. Such workspace features require a compatible workspace/project and resource entitlement where applicable. Their primary flow is: choose a scoped resource, configure and validate structured inputs, submit an atomic action, display progress or result, save an acknowledged revision where editing applies. The frontend provides accessible labeled controls and announced status; backend enforces authorization and schema validation; asynchronous work is idempotent with bounded retries. Failures retain the prior saved revision, show a safe actionable error and allow retry or cancellation. Keyboard equivalents, focus retention, bounded processing, latency/cost metrics and content-free audit events apply to every row. Media actions depend on a validated, isolated cloud processing plan; AI actions depend on a configured, approved provider. Unknown codec limits, provider availability and exact prices are deployment configuration, not universal promises. Acceptance checks below are minimums and must be expanded per release.

## Shared edge cases and verification

Uploads handle retry after disconnect, wrong checksum, quota exhaustion, cancellation race and untrusted metadata. Edits reject negative duration, missing asset, locked track and insufficient source handles. Exports reject unsupported codecs, missing inputs, stale authorization, unapproved cost and unsafe structured operations. Jobs record snapshot, attempt, duration, resource usage and reason category, without raw media, prompts or signed links. A mode change preserves fields it cannot expose, with an advanced-content notice. Generated content requires human review. These checks are specifications, not executed results.

Trace each row to its owner and phase above; concrete user interactions are in [screen specifications](../02-ux-ui/screen-by-screen-specifications.md), [Quick Edit](../02-ux-ui/quick-edit-experience.md) and [Pro Editor](../02-ux-ui/pro-editor-and-timeline-interactions.md). Engineering task and test linkage is maintained in the delivery and governance indexes. Detailed task IDs, measured budgets and fully enumerated per-feature contracts remain subject to the documentation audit and must not be inferred from this grouped catalog.

Caption styling has static, accessible presets in phase 2; animation, karaoke and multiple language tracks are phase 3. Transcript-based cut suggestions are phase 3 under AUD-002/CAP-001; semantic AI and natural-language editing remain phase 5. Role, phase and per-operation feature gating must be checked separately from JSON schema validity.
