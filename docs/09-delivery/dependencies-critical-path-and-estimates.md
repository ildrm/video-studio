# Dependencies, critical path and estimates

**Status:** proposed. **Owner:** technical program manager. **Method:** S = bounded change within a subsystem; M = multi-component feature; L = multiple subsystems and research; XL = architecture-dependent program. Bands describe relative uncertainty, not dates or staff commitments.

Critical path: legal and capability review → canonical schema/timebase and tenant security → persisted revision + upload/ingest → job lifecycle/isolated worker → deterministic render compiler and QC → seven-stage guided editor → advanced timeline/preview → professional media → AI/collaboration → measured hardening. Cloud foundation may begin with mock providers once the schema and security contracts are approved, but production launch must wait for all security, privacy, performance and restore gates.

Parallel streams: UX research and design tokens can run with threat modeling; media capability/codec spikes can run with identity and database work; API client tests can use contract mocks while APIs are developed; AI vendor evaluation and consent policy begin early; baseline safeguards T02-07 must precede phase-2 speech, while semantic AI evaluation expands in phase 5; capacity and cost models can start from synthetic benchmarks. Integration depends on stable interfaces. Platform delivery presets require revalidation immediately before release; legal review and provider availability may alter scope.

Track each epic's owner, dependencies, acceptance IDs, risk and confidence in [backlog](epics-user-stories-and-tasks.md). Re-estimate after spikes and record decisions; do not infer release dates from effort bands. Risks: unknown browser decoding support, mixed-frame-rate parity, large project performance, tenant isolation, codec licensing and volatile AI/vendor terms. Project schema, render compiler and storage correctness are high-impact reversible decisions only with migrations; approve them before parallel implementation diverges.
