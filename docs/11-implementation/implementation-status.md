# Implementation status

Status: **IN_PROGRESS** • Current focus: phases 0–2, initial local vertical slice • Updated: 2026-10-29.

The repository now contains a Next.js editor, a TypeScript API, PostgreSQL migrations, a Python media worker, npm workspaces, local Compose definitions and CI configuration. Real local password authentication creates scrypt-hashed accounts and database sessions; it is explicitly opt-in for development. Workspaces and projects are scoped to owners, revisions use optimistic `If-Match` and idempotency, and uploads are split and checksummed. The local supervisor uses PostgreSQL job records and leases, stages authorized input files, invokes FFmpeg/FFprobe via the media worker and publishes verified H.264/AAC MP4 artifacts for authorized download. This is not the planned production architecture.

The web app provides workspace/project creation, video upload UI, a bounded single-track clip timeline with trim, split, reorder, undo/redo, source audio controls, same-user reauthentication, save/conflict handling, one two-clip audio/video dissolve, render progress, cancellation and downloads. Native selected-source preview is explicitly approximate and does not show final multi-clip composition or the transition. Portrait, landscape and square presets exist for matching v1 canvases. Limited background audio and manual captions with bounded styles and trusted font assets are implemented; rendered-revision playback is available. Projects support rename, copy, archive, restore and search. The editor autosaves after one second and offers opt-in, scoped local draft recovery with seven-day expiry and a 2 MiB cap. New browser workflows still need interactive verification.

Earlier browser evidence includes: a browser created account/workspace/project, edited an API-seeded video, trimmed/split, saved, rendered and saw a download become available; crossfade was exercised; in-place reauthentication preserved unsaved work. The latest API regression passed 7/7 without skips, including real caption pixels, a real audio mix and H.264/AAC checks for all three aspect presets; concurrent migration runners both succeeded with four ledger rows. The current media worker suite passed 35/35 in a restricted Debian container; the host run passed 29 with 6 caption tests skipped because drawtext was unavailable, using a test-only FFmpeg shim. The suite covers crossfade, fractional audio, video-source audio, and rejection of insufficient decoded audio. Web tests passed 25/25; the latest API and web build and typecheck passed after the accessibility changes. Browser file-picker upload has not yet been verified. The latest Compose HTTP stack smoke passed through the web rewrite, including synthetic registration, upload/probe, caption render, download and project lifecycle; this is not an interactive browser test. Independent FFprobe checked the downloaded caption render: 1080×1080 H.264, 30 frames and one second, with one-second 48 kHz stereo AAC. The fresh standalone worker image passed all 35 bundled tests without a bind mount, with network disabled, a read-only root, noexec/nosuid 256 MiB `/tmp`, 2 CPUs and 2 GiB memory. These results apply to the tested code and environments. See [verification](testing-and-verification.md) for conditions and [matrix](feature-coverage-matrix.md) for scope.
